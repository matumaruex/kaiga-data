# 絵画データベース

実在する絵画の作品情報と、気持ちに合わせた展示のための**試験的な解釈データ**を管理する、2人で共有するデータリポジトリです。美術館アプリ本体のデザインや3D空間はここに置きません。

- **既存アプリの画像16作品を再取得して、保存元のSHA256と16/16一致。** 一致する画像の取得元・権利表示・ハッシュを共有台帳に記録。
- 16作品のうち11件は本リポジトリで調査した19作品に含まれ、残り5件は**旧アプリだけに存在する作品（感情分析は未移植）**。
- 19作品中、旧アプリにない8件について**Commonsの画像取得も8/8成功**。JPEG形式・取得時SHA256を記録。**作品画像の人による最終視認と解釈の審査が済むまでは、15候補の正式登録は保留**。
- **24/24作品の画像JPEG取得に成功**：[GitHubの画像検証結果](https://github.com/matumaruex/kaiga-data/actions/runs/39104302015)

## 現在の方針：AI向けの作品資料＋無料検索用タグ

**作品情報を1回調べて保存し、将来はプログラムで候補を絞ったうえでAIが最終選定する構成を想定。** ただし、AI APIの導入・選定ロジックはまだ行わない。通常のプログラムだけで選定する方式とも比較できるようにする。

- 保存する情報：基本情報・出典・画像・感情/主題タグ・短いAI用要約・合う具体的な状況・合わない状況への注意・背景と別の解釈
- **データは長文ほど良いわけではない**。検索段階は軽く、必要な作品だけの深い情報を読む
- 現在：本登録4作品と画像の最終確認待ちの候補15作品、合計19作品に検索プロフィールを付与。解釈の最終確認は未了
- [目的・情報設計・作業ルール](docs/data-policy.md)

## ファイル
- `data/artworks.json`：作品ごとの出典・事実・画像・解釈・レビュー状態
- `data/emotions.json`：感情（emotions）／空気感（tones）／主題（themes）の分類
- 作品内の `curation.search_profile`：AI用要約・適合する状況・選定上の注意。タグと両方使える
- `scripts/validate_artworks.py`：重複・ID・タグ・必須項目などをローカル検証
- `data/image-sources.json`：同じ作品の画像の入手元・利用条件・検証用SHA256。共有作品19件と旧アプリ由来5件を収録
- `scripts/check_image_sources.py`：画像台帳の整合性と（オプション）実画像の再取得・検証
- `docs/review-guide.md`：追加の前に確認するレビュー手順
- `docs/review-report-pilot-001.md`：試験登録4作品の見直し結果

## 検証
```bash
python3 scripts/validate_artworks.py
```
※この検証は形式チェック。画像の疎通確認や美術解釈の良し悪しまで保証しません。

## 出典と画像
作品ごとに `source.api_url` と `source.artwork_url` を記録しています。**作品情報はシカゴ公式API、画像はCommonsなどの公開画像源**を使います。

- `image.display_url` は公式IIIFの参照用URLです。現時点ではHTTP 403のため、**アプリの表示URLとしてそのまま使わない**。
- `data/image-sources.json` に16件の既存アプリ画像の出典・ハッシュ、および8件のCommons画像と今回検証したハッシュを記録。
- 実際のアプリでは、権利と取得を確かめてから画像をローカル同梱する。元のサイトへの毎回アクセスは不要。
- 共有データに画像ファイル本体はまだ同梱していません。データと画像の入手経路を分けることで複数アプリに再利用できます。

- [Art Institute of Chicago API](https://api.artic.edu/docs/)
- [利用規約](https://www.artic.edu/terms)
- 作品の元データは出典APIの条件に従い、説明文の転載ではなく独自の短い日本語分析を書いています。

公開条件は**作品と画像を区別**して確認してください。将来、他館の画像を追加する場合は各館の条件を再確認します。

### 共有画像を一括取得する

```bash

```

1行目：画像の出典台帳・作品ID・ハッシュ項目の形式チェック（ネット通信なし）。
2行目：**24点の画像を公開配信元から実際に取得し、SHA256で検証**。成功した画像を `public/artworks/作品番号.jpg` に保存する。これらはアプリへ同梱して利用できる。

画像はGitHub Actions上では実取得してテスト済み。ただし**画像の実ファイルをこの共有データリポジトリに追加したわけではない**。画像を使う個別アプリに保存する場合は、そのアプリ側で上記スクリプトを実行するか、出力済みJPEGを配置する。

### 自動チェック

[GitHub Actionsの確認ワークフロー](.github/workflows/check-artworks.yml)を用意した。通常のpush時は**形式チェック・感情カバレッジ・固定テスト入力の構造チェックのみ**、手動実行時はこれらに加えて**現在の公式APIの照合（画像HTTPは403で失敗する可能性あり）と代替画像のオンライン取得確認**を行う。コミットに`[verify-images]`を含めても代替画像のライブ検査を行う。接続失敗などで全候補を確認できなければオンライン確認ジョブは成功と扱わない。実行状況はGitHubのActions画面で確認する。

**注意：GitHub Actionsの成功だけで画像の視認・著作権の総合判断・感情との適合性が保証されるわけではない。** API通信不良時も検証スクリプトが未確認として記録するため、ログ内の成功/未確認件数を必ず参照すること。
