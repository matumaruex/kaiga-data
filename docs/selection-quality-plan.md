# 展示選定の品質試験（先にやるべきこと）

## なぜ作品数だけ増やさないのか
作品に「孤独」「希望」などを付けるだけでは、失恋・死別、好んで一人でいる時間・疎外感、複雑な感情を区別できない。
一枚単位のタグと、**入力文の状況・展示全体の構成**は異なる。
同じ入力に対して2つの美術館がデザイン比較をするため、共通の作品選定テストが必要。

## 使う資料
- `data/evaluation-cases.json`：架空の入力文12パターン（テスト入力用）
- `scripts/audit_coverage.py`：各感情タグの作品数（強度2以上、3）を診断

## 評価方法（1展示ごと）
各項目0〜3点で人間が採点。理想作品をあらかじめ1枚に固定しない。

1. **文脈理解**：単語だけでなく別れと死別、幸せな一人の時間などの違いを捉えたか
2. **作品との関連**：作品主題や背景に根拠があるか。色や連想の押し付けだけでないか
3. **展示全体の構成**：似た絵に偏らず、感情の多面性と余韻があるか
4. **鑑賞の自由**：無理な励まし・心理診断・作者意図の捏造をしていないか

別途、データの権利、画像表示、作品IDの正しさは合否判定（1つでも問題があれば公開禁止）。

記録フォーマット：
- 入力ケースID
- 選ばれた作品ID（順番も記録）
- 使ったデータのバージョン／コミットSHA
- 各4項目の点数
- 不適切な作品と理由
- 改善するタグ、作品情報、選定処理

**注意**：現時点では展示選定アルゴリズムは未完成。テスト項目を用意することと、動作テストに合格することは別。

## データ追加の優先順位
1. 作品画像が表示できるか、メタデータの現行API照合ができるか確認
2. 作品選定の評価ケースと、感情の不足を定量化
3. 苦手な文脈に合う作品を意識的に追加（ランダム収集は後）
4. **20〜30作品で簡単な展示選定を試作し、12ケースで採点**
5. 誤選定の原因を直してから次の20件へ
6. 50作品時点で再評価→100作品へ

## 2人の美術館を公平に比較
- 共有データ／アルゴリズムのバージョンを固定
- 作品選定を同じ入力でテスト
- UIデザイン・移動・鑑賞演出は別々に制作
- 評価する人はできれば同じ作品セットで比較

## 今の制約
- 初回4作品も画像表示未確認
- 追加15作品は現在のAPI・画像の実表示が未確認で本登録前
- 過去の第三者APIコピーで一致した画像IDを、現在の公式確認済みと扱わない
- GitHub ActionsのオンラインAPIテストは手動実行に分離し、失敗は失敗として扱う
- 外部サービスの有料AIは使わずに、まず再現可能な基準を作る

## 設計上の次の改善
- 単純な感情タグに加えて**状況（失恋・死別・郷愁・集団の中の孤独）**を別の軸として導入
- 感情スコアは鑑賞者の主観を含むため「事実」の欄に保存しない
- 作品分析は「画面で観察できること」「美術史の裏付け」「鑑賞の提案」に分ける
- 感情テストに合格するまで、選定ロジックを完成品とは呼ばない

**最優先で補強する方向**：喜び（強度2以上が0点）、未練・喪失感・寂しさ、怒り、期待。現時点の作品だけで「失恋に対応した展示10点」を安定して組むのは不可能に近い。

この表は「作品の質」ではなく**暫定タグの偏り**だけを示す。強い関連として登録された4作品も、画像の現物確認と人間の最終評価は済んでいない。

## 追加作品の選び方（変更後）
- 有名作品から順に登録するのではなく、テスト入力の**苦手な感情・文脈**から探す。
- 候補の事実確認と、作品の解釈を**別工程**に分ける。
- どれだけ似合いそうでも、現在の公式公開条件・画像実表示が確認できなければ展示用に昇格させない。
- 安心・悲しみだけでなく、**喜びや達成のような肯定的感情**も意識して確保。
- 同一地域・同一画家に偏りすぎないように、多様な美術館と日本画等を後続で調査する。
