# 絵画データベースの基本方針（2026-10-18）

## 目的
利用者の自由な感情から**作者が表現しようとした世界**に出会える、個人の企画展を作る。見た目の感情を当てるだけではなく、作者の意図と専門的な解釈を優先する。
目標は鑑賞体験の品質と、将来のAPI利用料の節約。作品データは2つの異なる美術館アプリで再利用する。

## 採用する構成（現段階）
1. **共通データベース**：GitHubに絵画の基本事実・出典・権利状態・検索用タグ・作品解釈を保存。
2. **候補抽出（原則無料）**：作品数が増えたら、タグ・主題・検索用の短文を利用して少数の候補に絞る。
3. **最終選定（将来）**：候補だけをAIに渡して、利用者の文章の複雑なニュアンスに合う6〜8作品を選ぶ。
4. **比較可能**：同じデータからルールベースのみの選定も試せるようにし、選定方式をデータに密結合させない。

**今は有料AI APIを使わない。** AI・プログラムの実装、料金、最終的な選定アルゴリズムの採用は後回し。
全作品の長文を毎回AIへ渡すよりも候補数を減らせれば、作品情報にかかる入力トークンの費用を節約できる。ただし全体の請求額は固定の指示文・入力文・出力トークンなどにも依存し、検索の取りこぼしも検証が必要。

## 保存する情報と役割
| 情報 | フィールド | 使い道 |
|---|---|---|
| 作品の事実 | `facts`, `source`, `image` | 作品の同定、画像、著作権、出典 |
| 主題・雰囲気・感情タグ | `curation.emotions`, `curation.emotion_strengths`, `curation.themes`, `curation.tones` | プログラムの一次検索 |
| **AIが読む短い要約** | `curation.search_profile.summary_for_ai` | 候補に残った作品を理解する |
| **適合する具体的な状況** | `curation.search_profile.fitting_situations[]` | 「同じ悲しさでも死別と失恋は別」などの違いを表現 |
| **選定に向かないケース・注意点** | `curation.search_profile.selection_cautions[]` | 取り違え・思い込み・暴力表現などへの注意 |
| 深い読みや歴史的背景 | `curation.interpretation`, `curation.source_context_note`, `curation.alternate_reading` | 最終選定時の精査、作品の詳しい解説 |
| 検証状況 | `review` / `verification` / `search_profile.review_status` | 未確認作品を公開可能と誤認しない |

### fitting_situations の形式
```json
{
  "situation": "人に囲まれているのに、誰ともつながれない",
  "reason": "人物が行き交っても関わり合わない画面から連想できる",
  "strength": 3
}
```
`strength` は1〜3の**暫定的な関連度**であり、科学的な感情の測定値ではない。

## 調査の順番（変えない基本作業）
1. 実在する作品と公式のID・出典、作品自体と画像の利用条件を確認。
2. 作者・制作年・作品の由来や背景を、可能な限り原資料・美術館の解説から確認。
3. 感情タグだけでなく、**具体的にどんな人のどんな気持ちに合うか**を簡潔に記録する。
4. 反対の読み・誤解の危険・出典未確認の部分を区別して残す。
5. 批判的レビュー：根拠、表現の強さ、偏り、既存データとの重複を見直す。
6. 画像の実表示が確認できた段階で、展示用として公開してよいか判断。

**文章を長くすることは目的ではない。** AIには短文で選定材料を渡し、必要に応じてのみ詳しい背景を参照させる。

## 今はやらない
- 感情の種類を無制限に細分化してタグを増やす
- 作品が足りない段階で複雑な検索アルゴリズムを作り込む
- 有料AI APIの常時呼び出し
- 似た意味の長文を大量に複製して、毎回すべてAIに渡す
- 未確認の画像や出典を「確認済み」として扱う

## 後で選定方式を決めるとき
最低限、入力文の文脈・候補作品との根拠・展示全体の組み合わせ・入力トークン量を比較する。
同じデータで「プログラムのみ」「プログラムで絞る＋AIで最終判断」を比較し、品質とコストを見て採用を決める。
