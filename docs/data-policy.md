# 絵画データベースの基本方針（2026-10-19改訂）

> **現行状況（2026-10-20）**：このページの選定「未実装」は企画当時の記録。現在は共有DB300作品、アプリの `codex/museum-preview` ブランチでAI選定の試験実装が稼働。新しい作品数・動作状態はREADMEとGitHubの最新実装を確認。

## 2026-10-20以降の検証ルール

専門的な作品情報の確認・AIによる分析・資料との照合を作業の中心とし、人間による美術史上の最終承認を必須としない。鑑賞者の感想は自由な任意の評価とする。

作品の検証状態は `review.ai_content_review_status`（解釈のAI検証）、`review.source_evidence_review_status`（出典との照合）、`review.image_subject_match_status`（画像と作品の一致）で管理する。各状態は `pending`、`verified`、`needs_revision` のいずれか。検証をしていない項目を確認済みにしない。 `curation.search_profile.review_status` は `evidence_review_pending` / `evidence_reviewed` / `evidence_review_needs_revision` とする。

`review.curatorial_review_status=approved` は上記の3項目が `verified` の場合だけ使用でき、人間の承認を意味しない。暫定状態の作品は試験展示に使用できるが、未確認の解釈を確定事項として提示しない。権利条件が不明な場合は再利用を保留する。

新方式への移行時に300作品のうち「専門家の解釈」と「制作背景」が同文の146件を `needs_revision`、残り154件を `pending` に設定した。第1回15件（保留2件を後日再調査）、第2回15件、第3回15件の合計45件を分離修正したため、現在の同文は101件。AI内容レビューは検証済み2件・確認待ち197件・要修正101件。原資料の新方式での内容照合は2件が `verified`、残り298件が `pending`。画像と作品の内容照合は全300件が `pending`。従来の人間承認フラグは廃止し、過去の「人間未承認」記載は当時の履歴としてのみ扱う。詳細は [レビュー手順](review-guide.md) を参照。

## 目的
利用者の自由な感情から**作者が表現しようとした世界**に出会える、個人の企画展を作る。見た目の感情を当てるだけではなく、作者の意図と専門的な解釈を優先する。
感情は展示への入口で、鑑賞の意味や反応を固定しない。目標は鑑賞体験の品質と、将来のAI API利用料の節約。作品データは2つの異なる美術館アプリで再利用する。

## 採用する構成（当初設計の説明を含む）
1. **共通データベース**：GitHubに絵画の基本事実・出典・権利状態・感情タグ・短い検索プロフィール・作品解釈を保存する。
2. **候補抽出（原則無料）**：感情を入口に、プログラムで`curation.emotion_categories.primary`と`secondary`を**両方**検索し、候補を絞る。主感情だけに限定しない。強度2〜3の主と強度1の補助を区別して持つが、主だけを機械的に採用するわけではない。
3. **AIによる最終選定（プレビューで試験実装中）**：絞った候補の`summary_for_ai`、適合理由、注意点と、作者の意図・専門家の解釈・制作背景等の`meaning_basis`を現在は一緒に渡している。重複は今後比較評価して整理する。利用者の文章との相性から展示作品を選び、作品数や選び方を固定配分しない。
4. **比較可能**：将来、同じデータでルールベースのみの選定とも比較できるよう、選定方式をデータに密結合させない。

**設計上の最優先事項**：AIに全作品を読ませたり、タグ抽出後に別のAI検索・再調査を何段も追加したりせず、プログラムで管理された索引を使ってAIの入力負担を抑える。感情タグは索引であり、作品の価値や鑑賞体験の予測を証明するものではない。

**タグなし作品の実際の制約**：タグ0件の作品はデータベースに保持するが、感情タグだけを使う一次抽出では候補にならない。これを解決したことにせず、勝手に追加の検索経路を設けない。必要なら将来、選定品質とコストを評価して方針を検討する。

**以下は選定実装前の計画段階の説明であり、2026-10-20現在の運用状況ではない。** 利用者入力から感情へ対応付ける具体的な実装も未決定。上記は将来の設計方針であり、稼働中の仕様ではない。候補数を絞ることで入力トークンを減らせる可能性はあるが、最終費用は入力・出力トークンや固定指示文にも依存し、取りこぼしの検証も必要。

## DBの情報を分ける：正本・検索索引・表示文（2026-10-20合意）

### 1. 基礎資料は作品の事実と意味の正本
`curation.meaning_basis` に、作者の証言・専門家の解釈・制作背景・視覚的特徴・不確実性を**互いの根拠や確実性を混ぜずに**記録する。出典は実際の該当箇所と照合する。作品の意味をAIや鑑賞者の入力感情に合わせて改変しない。基礎資料は「長く書く」ためのものではなく、**正確な内容を選定時に取り出すための正本**とする。

### 2. AI選定用には重複を最小化した索引を持つ
一次候補抽出には `emotion_categories.primary/secondary` と強度等の索引を使い、AI最終選定には必要な**作品固有の基礎資料**と、**どの入力状況との接点があるか・選定の注意点**を渡す。索引の感情的な見立てを作品の史実・作者の心理・鑑賞者の結論と混同しない。文章を複数欄に複製して「根拠が増えた」と扱わない。

- `curation.search_profile.summary_for_ai`：**現行プレビュー実装でAIに送信中**。ただし `meaning_basis` と重複することがあり、存在自体を必須の設計方針としない。**あり／なしの同一入力による選定品質・入力トークン・費用の比較**をして、明確な利点がなければ省略または正本からの自動生成へ移行する。検証前に削除しない。
- `curation.search_profile.fitting_situations` と `selection_cautions`：作品そのものの史実と異なり、選定時の関連性と注意点を示すため維持する。ただし `meaning_basis` の言い換えだけになるものは簡素化する。
- `curation.interpretation` / `source_context_note` / `alternate_reading`（旧形式3項目）：**現行の `bijutsukan` プレビュー版では正規化時の出力に使われず、AI選定や作品画面への直接の参照はない**。一方、共有DBの `scripts/validate_artworks.py` ではいまも必須。旧形式にも正本と異なる情報や注意事項があるため、**正本との差分を全件点検し、固有の有用情報を移したあと、他の利用先・過去互換・検証プログラムへの影響を確認してから統廃合**する。未確認の別アプリを含め、現時点では削除しない。
- 実行時に同義の文章を重複して送る必要があるかは、比較によって判断する。**文字数削減そのものを目的にせず、選定品質とAPI費用のバランスを優先**する。

### 3. 鑑賞者向けの作品解説は別物
**今はまだ鑑賞者向け本文を大量制作しない。** 後から一作品につき**1種類のきちんとした作品解説**を用意する。その際は**所蔵美術館の公式解説や学術資料を直接参照**する。短い `summary_for_ai` や `meaning_basis` を膨らませて再作文する工程を必須にしない。元の公式解説の中身がよければ情報を損なわず尊重し、翻訳・転載の権利条件を守りつつ、自然で正確な文章にする。文字数は作品ごとの出典と必要な情報によって決め、無理に固定しない。

鑑賞体験や感情に合わせて「感動させる」「驚かせる」文章へ最適化しない。何をどう感じるかは**鑑賞者が自分で決める**。作者の人生・技法・時代史を別ページに展開する多段階解説も現段階では作らない。

### 4. 監査を分け、二重作業を避ける
- **現在のDB監査**：選定用の作品情報として、原資料との内容一致、選定索引の根拠と整合、重複・不必要な複製を確認する。未照合は未照合のまま記録する。
- **将来の鑑賞者向け解説の品質検証**：原資料を直接参照し、文章ごとの内容正確性、読みやすさ、重要情報の欠落と転載条件を検証する。今のDBに先回りして大量の説明を増やすことは目的にしない。
- 現行のフィールド整理は**方針の確定であり、データ削除・型変更・アプリ実装修正の許可ではない**。別チャットで進行している同文修正やデータ更新と競合しないよう、構造変更前に影響範囲を確認する。

## 保存する情報と役割
| 情報 | フィールド | 使い道 |
|---|---|---|
| 作品の事実 | `facts`, `source`, `image` | 作品の同定、画像、著作権、出典 |
| **主・補助感情と互換索引** | `curation.emotion_categories.primary`, `.secondary`, `curation.emotions`, `curation.emotion_strengths` | **プログラムの一次候補抽出（主・補助とも対象）** |
| 主題・雰囲気 | `curation.themes`, `curation.tones` | 作品説明・解釈の手掛かり。検索段階を増やすことを必須としない |
| AIが読む短い要約（整理候補） | `curation.search_profile.summary_for_ai` | 現行選定で使用中。ただし基礎資料との重複は比較評価して残すか決める |
| **適合する具体的な状況** | `curation.search_profile.fitting_situations[]` | 「同じ悲しさでも死別と失恋は別」などの違いを表現 |
| **選定に向かないケース・注意点** | `curation.search_profile.selection_cautions[]` | 取り違え・思い込み・暴力表現などへの注意 |
| 旧形式の解説・互換欄（廃止検討） | `curation.interpretation`, `curation.source_context_note`, `curation.alternate_reading` | 現行プレビューの選定・表示には直接使われないが、DB検証では必須。固有情報と他の参照先を点検後に統廃合 |
| 検証状況 | `review` / `verification` / `search_profile.review_status` | 未確認作品を公開可能と誤認しない |

### fitting_situations の形式
```json
{
  "situation": "人に囲まれているのに、誰ともつながれない",
  "reason": "人物が行き交っても関わり合わない画面から連想できる",
  "strength": 3
}
```
`strength` は1〜3の**暫定的な関連度**であり、科学的な感情の測定値ではない。

## 感情分類の改訂（2026-10-19）
感情語彙は12種類から15種類に拡充し、「悲しみ」「畏敬」「慈しみ」を追加。「憧れ」「恐怖」は未採用。詳しい定義と「好奇心」の適用条件は [制作意図を中心にするキュレーション方針](intent-first-curation.md) に記載する。

感情タグは作品の収録条件ではない。作品に無理に感情を当てはめず、主感情0～2／補助0～2（合計0も可）とする。主の強度2〜3と補助の強度1は**感情との関連度**であり、作者発言の有無や資料の豊富さでは決めない。作者の言葉がなくても、個別作品の主題・構成・描写から具体的な関連を示せればタグを付けられる。

「静かな絵だから安心」「技法を研究したから好奇心」「背景に面白い裏話があるから好奇心」といった汎用的な理由だけでは付けない。感情によって緩さが違わないかを点検するが、件数を揃えるための調整はしない。鑑賞者が実際にどのように受け止めるかは自由とし、制作意図・専門家の解釈・鑑賞者との関連を区別する。詳しい判断基準は [キュレーション方針](intent-first-curation.md) を正本とする。

## 調査の順番（変えない基本作業）
1. 実在する作品と公式のID・出典、作品自体と画像の利用条件を確認。
2. 作者・制作年・作品の由来や背景を、可能な限り原資料・美術館の解説から確認。
3. 感情タグだけでなく、**具体的にどんな人のどんな気持ちに合うか**を簡潔に記録する。
4. 反対の読み・誤解の危険・出典未確認の部分を区別して残す。
5. 批判的レビュー：根拠、表現の強さ、偏り、既存データとの重複を見直す。
6. 画像の実表示が確認できた段階で、展示用として公開してよいか判断。

**文章を長くすることは目的ではない。** 現行プレビューでは候補作品の短い選定用情報と基礎資料の双方をAIへ渡している。必要性が重複する部分は品質・費用の比較で整理する。

## データの状態（2026-10-19確認）
- `data/artworks.json`：**登録作品と感情タグの正本**。感情の語彙は15種類、主感情は0〜2個・補助感情は0〜2個。作品数、感情別件数、タグなし作品数はデータ更新のたびに変わるため、この文書の固定件数を参照せず最新のJSONから集計する。2026-10-19には全感情の分類を一次見直しした。
- 作品には作者発言、美術館研究、制作背景、画面のヒント、検索プロフィールなどを分けて保存している。感情タグと検索プロフィールは暫定的なキュレーション判断であり、作品の最終公開承認ではない。
- `data/image-sources.json` には作品画像の出典・同定・検証情報を保存する。作品自体の権利と外部画像の提供・利用条件は別に扱う。
- 作品の出典調査・候補作品群の詳細な履歴は `data/candidates-batch-002.json` 〜各群のファイルと `docs/review-report-*.md` に残す。古いレビューに記載された「51点」「主1〜2」「100点到達前」などは作成当時の履歴であり、**現在の仕様・登録件数ではない**。
- 第1回展示試験は経験の記録であり、その反応を全鑑賞者に適用する成功法則として扱わない。展示結果を狙って分類を作り替えない。
- 選定ロジック、AI API、アプリ表示、最終的な画像・解釈・権利確認については、別途実装・検証が必要。
## 今はやらない
- 感情の種類を無制限に細分化してタグを増やす
- 作品が足りない段階で複雑な検索アルゴリズムを作り込む
- 感情タグによる一次抽出を迂回する追加AI検索や、固定的な「共感／意外性」枠の強制
- 有料AI APIの常時呼び出し
- 似た意味の長文を大量に複製して、毎回すべてAIに渡す
- 未確認の画像や出典を「確認済み」として扱う

## 後で選定方式を決めるとき
最低限、入力文の文脈・主感情と補助感情の両方の取りこぼし・候補作品との関連・展示全体の組み合わせ・入力トークン量を比較する。
同じデータで「プログラムのみ」「プログラムで絞る＋AIで最終判断」を比較し、品質とコストを見て採用を決める。
