# 鑑賞者向けの作品解説（2026-10-20、第1回）

## 目的・範囲
感情を入口に選ばれた作品を、鑑賞者自身の第一印象のあとでより深く理解できるように、作品ごとの一つの自然な日本語解説を用意する。解説の文章量は固定しない。共感・驚き・感動を誘導する作劇をしない。

本文は所蔵館の作品解説と学術資料を直接参照して執筆する。作者本人の発言・学芸員の読み・歴史的事実・鑑賞者が感じる可能性を区別する。専門資料の文章を転載・長文翻訳せず、日本語の独自表現で説明する。

## 保存形式
作品本体 `data/artworks.json` の各 `artworks[]` 要素の **トップレベル** に、必要な作品だけ次のオブジェクトを追加する。

```json
{
  "visitor_explanation": {
    "language": "ja",
    "text": "作品ごとに必要な長さで作成した解説本文",
    "source_urls": ["https://..."],
    "review": {
      "content_status": "verified",
      "source_status": "verified",
      "rights_status": "pending",
      "reviewed_on": "2026-10-20"
    }
  }
}
```

- `visitor_explanation` は **選定用ではない**。現行アプリの選定プロンプトと `curation.meaning_basis`、感情タグに自動転送・混合しない。
- 解説未作成作品はキーを持たない。空文章・仮本文を作らない。
- `language` は現在 `ja` のみ、`text` は完成した1種類の本文。段落は改行2つで分ける。
- `source_urls` は作品に即した一次・所蔵館公式・信頼できる専門出典を記録する。資料の存在だけでは内容確認にならない。
- `content_status` は本文各主張の正確性・確実性・読みやすさの編集検証。`source_status` は原資料の該当記述との照合。`rights_status` は文章の転載・翻訳・利用上の扱いを区別するための状態。`reviewed_on` はレビュー日（YYYY-MM-DD）。
- 各ステータスの語彙：`pending` / `verified` / `needs_revision`。不確かな状態を `verified` にしない。本文の `verified` には出典照合の `verified` が必要。
- `review.curatorial_review_status` など既存レビューは**別**。解説の検証完了を既存の全作品検証完了とは扱わない。

## 1件ごとの検証項目
1. 作品ID・題名・作者・制作年代と所蔵美術館の作品情報が一致。
2. 主な主張に実際の原資料・所蔵館公式・専門研究の根拠がある。URLだけでは合格にしない。
3. 画面から見た印象と、作者発言・研究者の読み・制作史を混同しない。未知の心理・人生は決めつけない。
4. 独立した日本語表現、わかりやすい文章、作品固有の深み、資料上の重要事項の欠落を確認する。
5. 他作品・複製・異版の取り違えとセンシティブな主題の説明を点検する。
6. 引用や画像の利用権は原資料の事実確認とは別に記録。未確認は `pending`。
7. データのキー一意性・URL・ステータス・非対象作品の不変性を機械検証する。
8. 5件単位で報告・承認された作品だけ収録する。

## 文体・構成の編集目安（2026-10-20 追記）

**これは文章の型を強制する規則ではなく、品質を見直す際の判断基準。** 作品ごとの原資料と内容が第一で、全作品を同じ構成・語尾に統一しない。

- 自然な美術館の学芸員の文体を基本とする。正確で読みやすいが、教科書や定型レポートのような説明調を必要以上に繰り返さない。
- 「〜を伝える作品です」「〜を見られる作品です」「〜を示す作品です」などの総括文を、毎回結びに置かない。情報が自然に完結していれば結論文を省いてよい。
- 画面の具体的な描写、筆遣い、色彩、構図、資料で確認できた事実、人物や物語について未解決の点など、**その作品にふさわしい場所で自然に文章を終える**。意味をまとめるのが有益なら総括してもよい。
- 無理に「絵へ視線を戻す」「謎を残す」「感動的な余韻を作る」といった別の定型を設けない。作品の感情や鑑賞者の反応を演出しない。
- 単調な定型表現を減らすために重要な歴史的事実や専門家の解釈を削らない。削るのは**重複したまとめや余分な言い換えが中心**。必要な専門用語には説明を加える。
- 構成・語尾・長さは全作品一律にしない。段落ごとの説明の順序も、作品と資料に応じて柔軟に決める。
- 見直し時は、「内容の正確性と重要な情報の保持」「自然に読めるか」「抽象的な教科書調の締めが重なっていないか」を順に確認する。
- 第1回5件にも第2回5件にも適用済み。採用した文章そのものは `data/artworks.json` の `visitor_explanation.text` を正本とする。

## チャットを変更したときの再開手順

1. 最初に `README.md`、`docs/data-policy.md`、このガイド、`data/artworks.json` と検証器 `scripts/validate_artworks.py` を参照し、**実際の最新登録件数を再計算する**。古いチャットでの件数を正本にしない。
2. すでに `visitor_explanation` がある作品を上書きしてよいと決めつけない。未作成作品から時代・主題・地域等が異なるおおむね5件を選ぶ。ジャンルを散らすために資料の薄い作品を無理に採用しない。
3. 各所蔵館の公式解説・学術資料を作品単位で確認し、自然な日本語で1件ずつ作成する。AI選定用の `meaning_basis` を引き延ばして代用しない。
4. **本文5件と作品ごとの根拠をチャットで先に報告し、ユーザーの承認を得てからGitHubへ書き込む**。微修正があれば修正内容も示す。
5. 既存300件と非対象フィールドの不変性をチェックし、`visitor_explanation` と必要最小限の文書だけ編集する。全300件に仮文章を付けない。
6. `README.md` の現行件数を更新し、`python3 scripts/validate_artworks.py` およびGitHub Actionsの `validate-format` の成功を確認する。未完了の場合は明記する。
7. 本文の検証状態・出典の検証状態・文章の権利状態は別々に扱う。解説の確認を既存の作品画像やキュレーション全体の検証済み扱いにしない。

**注意：これらは文章の創作的な型や鑑賞者の反応を固定する規則ではない。作品ごとの違いを尊重するための軽い編集方針。**
