# 1作品の検証済み版を保存する（2026-10-30）

## 既存の鑑賞解説を変更せず完成登録する（2026-11-05）

対象作品にすでに `visitor_explanation` が存在する場合も、1作品ごとの原資料・画像・本文・利用条件の実質審査を省略せず、既存の `complete_artwork.py` の `preview/save/check` を使用する。既存本文と審査入力の下書き `visitor_explanation`（本文・出典URL・レビュー欄）が**完全一致**することを条件とし、不一致なら既存本文を上書きせず拒否する。

- 審査用 `drafts/visitor-explanations/<ID>.json` には既存本文をレビュー状態ごと正確に複写し、出典の該当箇所・対象画像・利用条件を直接再照合する。同じ版の既存証拠は範囲と日付を明記して再利用する。
- `version.artwork_record_sha256` と `proposal.proposed_artwork_sha256` は、既存本文がある場合**既存本文込み**の対象レコードを参照する。従来の新規本文追加経路では本文が無い元版を参照する。
- `save` は元の本文と対象外299作品を変更せず、監査と版のハッシュに結びつけた `completion` だけを追加する。`check` は両経路を検証する。
- 既に完成記録のある作品・既存本文と下書きが異なる作品・必要な根拠に欠落がある作品は拒否する。既存本文の改稿はこの追加経路の対象ではない。作品別の人間承認は要しない。

## 2026-11-05以降の運用：同一版の証拠を再利用する

[共通運用v2の「現行の進め方」](artwork-completion-workflow-v2-through-2026-11-10.md#現行の進め方1作品ずつ証拠の再利用を優先2026-11-05合意)を、この登録手順よりも優先する（品質要件と既存ガードは維持）。

- 対象IDの最新版、下書き、選定資料、画像・出典の旧監査とハッシュを先に照合し、同一版で適用範囲が足りる証拠は引き継ぐ。確認したことのない内容を済みとしない。毎回画像JPEGの全バイトを取り直すことを無条件の追加手順にはしないが、既存登録ガードが現に要求する整合性は省略しない。
- 事実や本文を直したら変更箇所とその影響範囲のみ再照合。視覚的な同定・文章の権利判断・作者の証言との区別が未検証なら、旧SHA一致だけで完了にはできない。
- 完成前のテストは既存のpreview/save/check・構造・対象外不変・CIを基本にする。追加の新規ツールを作るのは再現性のある不足がある場合のみ。
- GitHub Actionsがqueued／実行中なら「システム待機」としてPRに保持。作品の「保留」に数えず、テスト成功やmainマージも偽装しない。何度も同じ作品調査をやり直さない。
- 作品内容のHOLD、修正が必要なREVISE、システム待機は別々に記録し、品質上のHOLDが出た作品は証拠を残して次へ。1作品ずつ進める方針は変更しない。


[共通運用v2](artwork-completion-workflow-v2-through-2026-11-10.md)に従う最初の登録経路。既存300作品のうち、鑑賞本文が未登録で、本文下書きと選定資料の限定修正案を検証した作品を1件ずつ正式DBへ保存する。人間の作品別承認は要求しない。

```sh
python3 scripts/complete_artwork.py preview --audit docs/artwork-completion-audits/met-435997-2026-10-30.json
python3 scripts/complete_artwork.py save --audit docs/artwork-completion-audits/met-435997-2026-10-30.json
python3 scripts/complete_artwork.py check
```

`preview`は書き込みなし。`save`は1作品だけを検証し、`data/artworks.json`を原子的に置換する。保存後はGit差分・CIを確認してmainへ統合する。すでに保存された作品は`check`で検証し、二重登録しない。

## 検証の責任

AIは原資料の該当箇所と画像を直接確認し、制作とは別工程で再参照する。史実・解釈・感情との接点・本文類似・利用条件の判断を監査JSONに残す。同じAIによる別工程を用いた場合は、その方法と限界を明記し、別担当の独立性を装わない。

プログラムはAIの判断を生成しない。PASSでも保留事項や登録不可が残る記録を拒否し、画像・下書き・修正案・元の作品の版を照合する。さらに一時コピー上で既存の構造・300作品スナップショット検査を実行し、対象外の作品を変更しない。画像の今回取得バイトが登録値に一致しないケースは、この最初の登録経路では受け付けない。

`rights_check.result=PASS`は、対象版の本文・画像にDB保存を妨げる重大な未解消事項を認めなかったというレビュー判断。画像のPublic Domainを文章に拡張せず、法的な非侵害保証や個別許諾の取得とは扱わない。

## 互換性と証拠の保存

本文と既存レビュー欄は検証した下書きのまま保存する。過去のpendingや人間承認台帳を偽の承認で埋めない。新しい`completion`欄は監査ファイルと正式DBの内容指紋を結び付ける。指紋から除くのは`completion`自身だけで、本文・出典・選定情報等が変われば検査は失敗する。作品の表示と選定に必要な従来のデータ構造は保持する。

`check`は、このcheckoutに保存された証拠に基づく完成・未完成・保留の件数を表示する。別ブランチだけにある保留記録は数えない。PR #3の過去の監査や下書きは削除せず、今回必要な対象作品の証拠だけを引き継ぐ。

この初期実装は、既存解説の置換、301件目以降の新規登録、異なる画像バイトの再照合には未対応で、入力を拒否する。新規下書きからの登録も同じ根拠条件を満たす必要がある。全300作品を完成済みとは扱わない。
