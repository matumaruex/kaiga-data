# 第2段階：新しい絵画の登録、多様性と権利（2026-11-10）

## 「続きして」での標準作業

1. 最新mainの作品DB、画像台帳、感情語彙、このガイド、v2品質基準、resume文書の先頭を確認する。完成済み300件を再登録しない。
2. 現存作品を文化圏・制作年代・題材・様式・技法・作者・所蔵館・15感情の主補助タグで確認し、未収録または少ない領域を候補探索の優先対象とする。地域や様式のフィールドがない場合は、出典付きの作品情報から妥当な範囲で分類し、分からない場合は「不明」とする。作者の国籍を画中の文化圏と短絡させない。
3. 件数均等化は目的としない。最優先は作品自体の価値、独自性、信頼できる作品別資料、公開画像の確実性。偏りを理由に低品質作品を入れず、感情タグを捏造しない。重複ID、同作の別画像、同題異作、模写・作者帰属の曖昧さを調べる。
4. 候補を1作品ずつ調査し、正式所蔵館ID、基本事実、絵の実画面、出典該当箇所、作者の発言と研究者の解釈の範囲を区別する。AI選定用のmeaning_basis・検索プロフィール・感情タグと、鑑賞者向け独自日本語解説を作る。感情タグ0件も認める。
5. 著作権・利用条件は三つに分ける。(a) 作品自体の著作権消滅／PD表示、(b) **公開画像ファイルの利用条件**、(c) **現代の美術館解説文の著作権**。単に古い絵だからと一括許可しない。日本の著作権の死後70年原則にも例外がある。作品のPD/CC0表示と画像ライセンスを対象作品・画像に照らして確認し、別の権利が不明なら保留。出典文は長文転載・ほぼ逐語の翻訳でなく独自に記述する。
6. 公開JPEGを実取得し、バイト数・SHA256・所蔵IDと図像の視認確認を記録する。SHA一致は図像同定の代わりではない。**公式作品解説に依拠する本文の重要主張は、実際に作品別解説本文を読み、主張と該当箇所の対応を監査記録に残す。公式APIの作品情報や画像検査だけでは「解説照合済み」にしない。解説本文が無い・読めない場合はその事実を記録し、確認できた資料と画面観察の範囲だけで記述する。** 本文の重要主張と一次出典、画像・権利について制作とは別工程で実質監査し、根拠と限界を保存する。推測による作者心理や感情タグの数合わせをしない。
7. 必須項目と監査が合格した版だけ scripts/add_artwork.py preview → save → check を通してDB・画像台帳へ1件ずつ新規登録する。GitHub CIに合格しmainへ統合後に正式完成数を更新。失敗・未解決は保留またはシステム待機として記録し別候補へ進む。チャット間の自動進行は約束せず、次回は「続きして」で再開する。

## プログラムと配信の対応範囲

- 導入時の新規登録ソースは **Met（met-ID）とシカゴ美術館（aic-ID）**。サイトの作品IDと画像ホストの許可、既存データの形式を維持する。他館に広げる際は公式API/所蔵館ID・ライセンス・画像ホスト・画像の同定・アプリの安全な配信・テストを一式で追加する。未対応の館を強制登録しない。
- baseline-300-ids.jsonに保存した既存300作品のID集合は削除しない。画像台帳の整合と既存作者帰属は維持し、新規作品には必ず1件の画像台帳記録とv2完成監査を付ける。
- 登録案は drafts/artwork-additions/ID.json（作品レコードと画像台帳レコード）、解説と出典の原稿は drafts/visitor-explanations/ID.json、監査は docs/artwork-completion-audits/ID-日付.json に置く。登録監査のスキーマは scripts/add_artwork.py に従う。監査フラグだけを機械的に埋めて「調査済み」としない。
- アプリはmainのDBをおおむね24時間キャッシュし、再デプロイ時にはmainの最新版を初期DBへ同期する。追加直後の全利用者への即時反映までは保証しない。

**短い再開指示：「美術館の続きして」。** 現在の作品分布の確認から新規候補を選び、v2品質を落とさず1作品ずつGitHubへ保存していく。
