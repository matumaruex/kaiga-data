# 制作意図を中心にするキュレーション方針（2026-10-19改訂）

> **現行状況（2026-10-20）**：この文書の「118作品」「選定未実装」等は作成時点の記録。現在は作品DB300件で、別リポジトリ `matumaruex/bijutsukan` のプレビューブランチに候補抽出とMiMo選定が実装済み。方針は継続するが、実装と登録件数の正本はそれぞれの最新コード・データを参照。

## 美術館の目的
利用者が自由に表現した感情を入口に、作者が何を表現しようとしたかに出会う。共感だけでなく、予想外の発見、第一印象と制作背景のずれ、作品への没入も価値とする。見た目だけで作者の心理を推定しない。

## 情報源の優先順位
1. 作者自身の言葉（手紙・日記など）。別作品や連作への言葉なら、その範囲を明記する。
2. 美術館の研究・信頼できる専門的解説。作者の明言と混同しない。
3. 制作当時の背景。作者の伝記と個別の作品を結ぶ根拠が必要。
4. 色彩・題材・構図は表現を理解するヒント。外見だけから制作意図を決めない。
5. それでも不明な意図は「確認できない」とする。感動的な物語で埋めない。

## 作品データに用いる軽量構造（2026-10-19現在118作品）
- `curation.meaning_basis.author_intent`：作者発言の状態と要約、出典。未確認なら本文も出典も `null`。
- `curation.meaning_basis.scholarly_interpretation`：専門家の読解とURL。
- `creation_context`：制作背景。
- `visual_clues`：画面と意味を結ぶ観察点。
- `uncertainty_note`：どこまで分かり、何は分からないか。
- `curation.emotion_categories.primary`：主要感情への入口を0～2個。確かな接点がなければ主感情0個も認める。
- `curation.emotion_categories.secondary`：弱い補助を0～2個。
- `curation.emotions`・`emotion_strengths`：従来方式との互換索引。主タグは強度2か3、補助は1。

感情タグは作者の感情の診断ではなく、利用者の自由な気持ちと歴史的な作品の意味を接続する**低コストな検索索引**。感情は展示への入口であって、鑑賞後の解釈や感想を誘導するものではない。作者の言葉・研究の確かさと、感情との関連の強弱は別の軸として扱う。

## 感情タグの付与基準（2026-10-19確定）
- **目的**：プログラムが感情で作品候補を安価に抽出できるようにする。作品の感情を証明したり、作品の意味・鑑賞結果を固定したりするための分類ではない。
- **採用基準**：利用者の「その感情を感じたい」という入口に、**その作品固有の主題・具体的な構成・描写・意味**の何が自然につながるかを短く説明できること。関連が自然なら採用し、鑑賞者が必ずそう感じると断定しない。
- **作者の意図と資料量**：作者の直接発言や美術館研究は重要な根拠だが、発言が確認できないことだけを理由にタグを外したり強度を下げたりしない。画面の具体的な要素・題材・信頼できる解釈との接点も認める。作者本人の感情、画中人物の感情、鑑賞者への入口は混同しない。
- **主2〜3／補助1**：数値は*その作品と入力感情との関連の強さ*の暫定評価であり、研究資料の充実度・証拠の確実性・鑑賞者の感情の強度ではない。主感情は比較的明確な関連（2〜3）、補助感情は具体的だが弱い関連（1）。作品ごとに主0〜2・補助0〜2とし、必要なければ0件でもよい。
- **安易な拡大を避ける**：「静かな風景だから安心」「画家が技法を研究したから好奇心」「背景に意外な逸話があるから好奇心」だけでは足りない。安心なら休息・保護・居場所・安堵など、好奇心なら画面に現れる謎や具体的に探れる主題・表現など、その作品固有の結び付きを確かめる。
- **分類の偏り**：「安心」「好奇心」など使いやすいタグだけが過剰に付いていないかレビューする。ただし感情ごとの件数を同じにするために追加・削除はしない。タグが付かなくても作品の収録価値は下げない。
- **自由な鑑賞**：展示のために共感、意外性、違和感、感動などの反応を作為的に作らない。選んだ理由は説明可能にし、鑑賞者がどう受け取るかは開いたままにする。

## 感情語彙と分類根拠の改訂（2026-10-19）
既存の12感情は残し、「悲しみ」「畏敬」「慈しみ」の3感情を追加して15感情とする。「憧れ」「恐怖」は今回は追加しない。語彙数を揃えるために作品のタグを増やさない。

- **悲しみ**：苦痛、不幸、別れなどに対して感じる心の痛み。何かを失った事実に限定される「喪失感」や、人との隔たりを感じる「寂しさ」と区別する。
- **畏敬**：自分を超える大きな存在や自然に圧倒され、恐れと感動・敬意が入り混じる気持ち。危険を恐れる「不安」と同じではない。
- **慈しみ**：人や命を大切に思い、守り、いたわりたいという温かな気持ち。主題タグ「愛情」とは別に、鑑賞者の感情の入口として根拠があるときだけ採用する。

**好奇心の定義**：未知の世界や物事、人物、現象、意味などについて、知りたい、確かめたい、探りたいと感じること。作品の主題・表現・制作背景に、その気持ちとの具体的な接点がある場合にだけ付与する。「作者が研究熱心だった」「背景に面白い裏話がある」というだけでは足りない。一方、初見ですぐ謎を感じる作品だけに限定せず、背景を含めて作品固有の問いがあるかを確認する。

**感情タグを無理に付けない**：主感情0～2、補助感情0～2とし、適切な関連が確認できなければ感情タグ0個でも作品は収録できる。補助感情だけが残る作品も認める。主感情は強度2～3、補助感情は1とし、主感情への機械的な格上げはしない。感情に関係なく重要な制作背景、技法、美術史、主題、雰囲気は、それぞれの既存欄に記録する。感情タグの有無だけを作品の価値や収録条件としない。

**選定時の確認**：鑑賞者の入力した感情と、作品の具体的な何が結び付くかを説明できるか。感情と関連さえあればよく、その後の鑑賞体験を事前に決めない。

## 展示候補の選定設計（未実装・2026-10-19合意）
1. **感情を入口にする**：利用者の入力に対応する感情を扱う。入力文をどう解釈して感情へ対応付けるかの実装方法は未決定。
2. **プログラムで軽く抽出する**：共通データベースの`primary` **および `secondary` の両方**を検索対象にして候補を取り出す。主・補助とも候補になれる。強度は関連を判断する参考値であり、主感情だけで候補を固定しない。候補抽出のために追加のAI検索、全作品の長文読込、複数段の調査処理を必須にしない。
3. **AIには絞った候補だけ渡す**：`summary_for_ai` と必要な短い適合理由・注意事項をもとに利用者の文章との接点を判断する。詳細な資料は必要な場合のみ参照する構想。実際のAI呼び出し・料金・性能は未検証。
4. **数合わせをしない**：主と補助の作品数、共感・対照・意外性の作品数に固定配分を設けない。入力感情との無理のない関連を条件として、展示内の新しい出会いと解釈は鑑賞の自由から生じるものとする。
5. **タグなし作品の扱いを正直に区別する**：タグ0件でもデータベースに残す価値はあるが、*感情タグだけによる一次抽出*では候補に入らない。現在合意した軽量方式のために追加のAI探索や別ルートを勝手に増やさない。タグなしの展示機会をどう扱うかは、将来の実測を踏まえて別途検討する。

「6作品中、共鳴4／違う向き合い方1／意外な出会い1」は以前の試験仮説であり、**必須比率ではない**。実装前に品質・候補の取りこぼし・トークン費用を検証する。

## 品質管理
`scripts/validate_artworks.py` はタグの上限、本人発言の状態、出典URLと互換タグの整合を確認する。これは記述内容の美術史的正確性や展示の魅力を自動保証しない。人間による絵画史の判定を利用者に要求せず、作品の資料に基づく修正を積み重ねる。
