# 絵画の共通品質基準 v2

この文書は作品1点の完成判定に使う品質基準。新規登録の手順は [新規作品の追加手順](artwork-expansion-v2.md)、作業の開始位置は [再開メモ](resume-artwork-work.md) を参照する。

## 作品の完成条件（1作品単位）

次の全てを、可能なら同じ調査で揃える。

1. **同定と事実:** 所蔵館・作品ID・題名・作者（帰属不確実性を含む）・年代・素材など、実際に提供されている情報と一致する。異版・模写・同題作を取り違えない。
2. **作品画像と利用条件:** 画像がその作品を示し、実際に取得・表示できる。URLやハッシュが一致するだけで「正しい絵」とは判定しない。作品本体の権利、画像の配信条件を区別する。
3. **選定用資料:** `curation.meaning_basis` に作者本人の証言、所蔵館／研究者の解釈、制作背景、画面の根拠、未確定事項を混同せず記録する。`fitting_situations`・`selection_cautions` は作品固有の根拠に合わせる。同じ解説の無意味な複製は作らない。
4. **感情タグ:** 主・補助タグ、強度が資料・画面と矛盾しない。合わなければタグ0件でよく、件数合わせをしない。
5. **鑑賞者向け解説:** 原資料を直接参照した自然な日本語の**1種類の本文**と出典URLを保持する。文字数や結語を固定せず、事実・本人の発言・研究者の読み・推測を区別し、資料から情報を捏造しない。所蔵館文章の長文転載や実質的な丸写し・逐語翻訳をしない。
6. **根拠確認:** 重要な主張について、出典ページの**該当箇所の内容**を確認する（URL記載のみでは不可）。資料が足りない／内容が食い違うなら無理に合格させない。
7. **利用条件:** 画像のPublic Domain／CC0表示を、そのページの学芸員解説の文章の自由利用と混同しない。公表・配布する本文・画像に未解消の重大な条件問題があれば完成扱いにしない。AIの文章類似度判定は法的な許諾や非侵害の保証ではない。
8. **別工程の実質審査と機械検査:** 制作とは別の工程で出典本文と画像を参照し直し、史実・解釈・抜け・誇張・文章類似・適合タグを確認する。プログラムは構造、ID重複、参照、対象外レコードの不変性などを検査する。同一AIの別工程は、別モデルや外部専門家による審査と称しない。両方合格した版のみ完成とする。

### 品質を守るための線引き

- AI検証に必要な出典本文や画像を取得できないときは、**検証不能**として保留。作者の意図や著作権を推測で埋めない。
- AIが自分の生成文を言い換えて確認するだけでは独立監査としない。別パスで原資料を調べ直し、作品ID・重要主張を直接照合する。
- 重大な疑義が解消できない作品を、件数を稼ぐために「合格」にしない。保留して**次の作品に移る**。
- 1作品の完成は、全アプリの選定品質や公衆公開の最終検証が完了したという宣言ではない。公開の設定・ライセンス／利用規約確認は別途アプリ側でも行う。

## 作業の扱い

- 1作品ずつ調査・制作・別工程審査を行い、合格版を保存する。続きの作品に進む際も審査を省略しない。
- 既存の証拠が対象作品・対象版に対応し、範囲や日時を確認できるなら再利用する。以前の確認を「今回実施」とは書かない。
- 出典不足・作品画像の不一致・権利の問題は保留。登録や通信の一時的な障害は作品内容の不合格と区別する。
- 合格版がGitHubの `main` に入ったときだけ完成数に含める。アプリへの公開反映とは区別する。
- 登録結果は完成数と保留理由を簡潔に伝える。必要な検査・監査の内訳は記録に残す。

## 4. 進捗表示と検証証拠を分離する

**利用者に見せる作品ごとの進捗は3区分だけ。**

| 表示 | 判断 |
| --- | --- |
| 未完成 | 当該版の全条件に対する合格記録がない／制作中 |
| 完成 | **当該版**が独立AI監査と機械検証に合格し、正式DBへ保存済み |
| 保留 | 出典不足、作品・画像不一致、権利条件などの未解決理由がある |

- 多数の `content_status` / `source_status` / `rights_status` や作品全体のレビュー欄を、日常作業の独立した「完了待ちタスク」にしない。検証の内訳は**1つの機械可読な監査記録**に集約し、進捗表示はそこから算出する。
- 監査記録には作品ID、検証対象の版（Gitのコミット／内容指紋など）、使用した出典と該当箇所、画像照合・品質・利用条件の判定根拠、独立検証の方法、`PASS / REVISE / HOLD`、保留理由を残す。**監査ログは証拠であって、人間の署名・承認台帳ではない。**
- 制作中の内訳は必要に応じてデバッグできるが、ユーザーへ「内容は完了・画像は未完・権利は保留」などの大量の手動ステータス更新を要求しない。
- 過去のフィールドは、互換性維持のため**移行実装完了まで保存**。新監査方式へ移行できた版から整理する。単に既存の `pending` を一斉に `verified` へ書き換えない。
- 一度完成しても、出典撤回・画像差し替え・実質的な本文改稿など、根拠を左右する変更があればその作品だけ再検証。無関係な全件再監査はしない。
