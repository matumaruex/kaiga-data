# 絵画データベース完成・追加運用 v2（2026-10-28）

> 2026-10-30実装追記：[既存作品の検証済み下書き1件を保存する経路](artwork-registration-v2.md)を追加した。既存解説の置換・新規作品登録・アプリ全体の移行は引き続き未実装。以下の目標仕様と完了条件を維持する。

> **合意した目標仕様。実装移行中。** 既存プログラムや `data/artworks.json` は、まだこの仕様に対応していない。以下は今後の制作・検証・移行の判断基準であり、「文書を書いた＝自動検証が動く／既存作品が完成した」とは扱わない。
>
> **最優先:** 人間の作品別チェック・本文承認を必須にしない。作品を1件ずつ「調査→制作（または修正）→独立AI＋プログラムでまとめて確認→合格なら保存して次へ」にする。品質保証を名目に、5件・10件ごとの承認待ちや細かな進捗フラグを増やさない。

## 0. 最終的に目指すもの

- **第1段階：すでに登録された300作品を完成させる。** 300件は試験的に粗く集めた土台。登録されているだけでは完成ではない。既存の使える事実・画像・文章は再利用し、疑わしい点／足りない点のみ再調査・修正する。
- **第2段階：新しい作品を増やす。** 301件目以降は、最初から共通の完成条件に達してからDBへ正式登録する。「仮登録300件→後でまとめて直す」という方式を繰り返さない。
- **完成条件は両段階で同じ。** 既存だから甘く判定しない。工程だけが「既存を修復する」か「新規に作る」かで違う。
- **現在のアプリとの互換性を守る。** `meaning_basis`、感情タグ、`fitting_situations`、`selection_cautions` は現行AI選定で使われる。削除や置換はアプリ側も更新して試験してから行う。

## 1. 「完成」の共通条件（1作品単位）

次の全てを、可能なら同じ調査で揃える。

1. **同定と事実:** 所蔵館・作品ID・題名・作者（帰属不確実性を含む）・年代・素材など、実際に提供されている情報と一致する。異版・模写・同題作を取り違えない。
2. **作品画像と利用条件:** 画像がその作品を示し、実際に取得・表示できる。URLやハッシュが一致するだけで「正しい絵」とは判定しない。作品本体の権利、画像の配信条件を区別する。
3. **選定用資料:** `curation.meaning_basis` に作者本人の証言、所蔵館／研究者の解釈、制作背景、画面の根拠、未確定事項を混同せず記録する。`fitting_situations`・`selection_cautions` は作品固有の根拠に合わせる。同じ解説の無意味な複製は作らない。
4. **感情タグ:** 主・補助タグ、強度が資料・画面と矛盾しない。合わなければタグ0件でよく、件数合わせをしない。
5. **鑑賞者向け解説:** 原資料を直接参照した自然な日本語の**1種類の本文**と出典URLを保持する。文字数や結語を固定せず、事実・本人の発言・研究者の読み・推測を区別し、資料から情報を捏造しない。所蔵館文章の長文転載や実質的な丸写し・逐語翻訳をしない。
6. **根拠確認:** 重要な主張について、出典ページの**該当箇所の内容**を確認する（URL記載のみでは不可）。資料が足りない／内容が食い違うなら無理に合格させない。
7. **利用条件:** 画像のPublic Domain／CC0表示を、そのページの学芸員解説の文章の自由利用と混同しない。公表・配布する本文・画像に未解消の重大な条件問題があれば完成扱いにしない。AIの文章類似度判定は法的な許諾や非侵害の保証ではない。
8. **一括検証:** 制作者とは**別のAI検証工程**が出典本文と対象画像を再参照し、史実・解釈・抜け・誇張・文章類似・適合タグを検証する。さらにプログラムで構造、ID重複、参照、対象外レコードの不変性を確認する。両方合格した版のみ完成とする。

### 品質を守るための線引き

- AI検証に必要な出典本文や画像を取得できないときは、**検証不能**として保留。作者の意図や著作権を推測で埋めない。
- AIが自分の生成文を言い換えて確認するだけでは独立監査としない。別パスで原資料を調べ直し、作品ID・重要主張を直接照合する。
- 重大な疑義が解消できない作品を、件数を稼ぐために「合格」にしない。保留して**次の作品に移る**。
- 1作品の完成は、全アプリの選定品質や公衆公開の最終検証が完了したという宣言ではない。公開の設定・ライセンス／利用規約確認は別途アプリ側でも行う。

## 2. 第1段階：既存300作品を完成させる

1. 最新の `main`、下書きPR、既存の制作記録を突き合わせ、そのIDが「本番解説あり／下書きあり／未着手」のどれか確認。**既存の完成済みと判定できる部分は再制作しない。**
2. その作品の事実・画像・意味資料・タグ・解説を読み、公式ページ／専門資料を確認。既存の誤り・弱い根拠・不足だけを修正する。**解説だけ書いて他の既存情報を未確認のまま『作品完成』にしない。**
3. 本文・選定用情報の修正は、可能なら同じ原資料調査から作る。解説の文面を選定用に無理やり転用せず、目的の異なる情報を適切に残す。
4. 独立AIが原資料・画像と照合し、形式テストも行う。問題があれば直して再試験。解決不能なら保留理由を記録し、次へ。
5. **合格した1作品を保存し、その版を完成として集計する。** 5件下書き・10件報告・人間承認・承認ハッシュ台帳は不要。中断に備えて1作品単位で保存する。

### 現在の作業資産を引き継ぐ（2026-10-28確認）

- `main` の300作品のうち、鑑賞者向け解説は**100件登録**されている。ただしこれだけでv2の全条件合格とは認定しない。
- [作業中のDraft PR #3](https://github.com/matumaruex/kaiga-data/pull/3) には別の**100件の下書き**がある。これらを捨てたり、同一IDで新規作成し直したりしない。残り**100件は解説未着手**（PRの説明時点）。
- Draft PR #3にある監査結果では、100下書きの文章権利確認は未完了。公式ページ冒頭との予備比較で**57件が優先改稿・確認対象、他43件も追加確認が必要**。これは「57件が違法」という意味ではない。未解決の資料差・画像ハッシュの照合課題も個別に記録されている。どの100件も**自動的に完成へ昇格させない**。
- 作業PRの更新状況は変わる。実行時には最新件数をDB・ブランチから再計算し、この日付の数字を固定値にしない。

## 3. 第2段階：301件目以降を追加する

1. 候補を探す。既存ID・作者・同題・異版・複製との重複を先に調べる。
2. 公式作品ID、所蔵館、事実、原画像、利用条件を確認。ここで不可なら登録せず次候補へ。
3. 一度の調査から `meaning_basis`・感情タグ・適合状況／注意点・鑑賞者向け解説を作る。資料が薄い作品を水増ししない。
4. **第1段階と同じ独立AI検証＋機械検証**を実行する。
5. 合格したものだけDBと画像台帳へ整合した形で正式登録し、1件ずつ保存する。未合格の候補は本番DBへ暫定登録しない。

新規追加の際は `check_catalog_snapshot.py` の「300件固定」など、旧規模を前提にした検証を意図的に更新する。作成・選定時は任意の一括処理でもよいが、人間へのバッチ承認を条件にしない。

## 4. 進捗表示と検証証拠を分離する

**利用者に見せる作品ごとの進捗は3区分だけ。**

| 表示 | 判断 |
| --- | --- |
| 未完成 | 当該版の全条件に対する合格記録がない／制作中 |
| 完成 | **当該版**が独立AI監査と機械検証に合格し、正式DBへ保存済み |
| 保留 | 出典不足、作品・画像不一致、権利条件などの未解決理由がある |

- 多数の `content_status` / `source_status` / `rights_status` や作品全体のレビュー欄を、日常作業の独立した「完了待ちタスク」にしない。検証の内訳は**1つの機械可読な監査記録**に集約し、進捗表示はそこから算出する。
- 監査記録には作品ID、検証対象の版（Gitのコミット／内容指紋など）、使用した出典と該当箇所、画像照合・品質・利用条件の判定根拠、独立検証の方法、`PASS / REVISE / HOLD`、保留理由を残す。**監査ログは証拠であって、人間の署名・承認台帳ではない。**
- 制作中の内訳は必要に応じてデバッグできるが、ユーザーへ「内容は完了・画像は未完・権利は保留」などの大量の手動ステータス更新を要求しない。
- 過去のフィールドは、互換性維持のため**移行実装完了まで保存**。新監査方式へ移行できた版から整理する。単に既存の `pending` を一斉に `verified` へ書き換えない。
- 一度完成しても、出典撤回・画像差し替え・実質的な本文改稿など、根拠を左右する変更があればその作品だけ再検証。無関係な全件再監査はしない。

## 5. 実装の優先順（この文書だけではまだ実装されない）

1. **現状の保全:** `main`、PR #3の下書き100件と監査記録、既存承認履歴を保持し、進捗をIDで照合する。
2. **一括監査方式を作る:** 1作品ごとのAI監査入力・出力（出典を実際に読んだ根拠つき）と検証ログの仕様を実装。自動スクリプトだけで「AI照合済み」を装わない。
3. **登録コマンドを変更:** 本文・出典・画像など必要条件の検証ログを満たせば、**人間承認なし**で1件を正式登録できるようにする。ハッシュ付きユーザー承認台帳は、互換性に支障がない段階で廃止。未検証の自動昇格は不可。
4. **スキーマ・検証器・アプリを連動更新:** 複数レビュー状態を内部の1監査と3区分の進捗に統合し、`kaiga-data` と `bijutsukan` の取り込み・選定・表示テストを通す。
5. **3種類を試験:** 本番解説あり、PR #3下書きあり、完全未着手の各1作品で、制作・独立検証・合格・保存・次作品への遷移を確認。**人間の作品承認を求めない。**
6. **既存300件に適用してから、新規追加を開始。** 一部の作品が保留の場合はそのまま保留一覧に置き、他の作品を進める。

## 6. 変更対象と過去の記録

- 新運用の参照文書は**このファイルを優先**する。ただしコード移行前の実操作は現行スクリプトの制限が残る。実装変更後に `docs/visitor-explanation-guide.md`、`docs/visitor-draft-workflow.md`、`docs/review-guide.md` とREADMEを新運用に合わせて簡潔化する。
- 過去の制作報告と監査ログは履歴として保持し、**過去に存在した人間の承認条件を新しい作品へ要求しない**。
- 解説の1作品1本文、根拠の直接照合、作者本人と研究者の区別、感情誘導しない文章、非転載、画像真正性、既存データを壊さない自動テストは継続する。
